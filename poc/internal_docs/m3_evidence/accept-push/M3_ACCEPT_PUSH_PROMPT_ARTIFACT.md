# 2. New upstream fact that changes the search space

Before any heavy run, verify against the exact Nchan 1.3.8 documentation/source:

```text
nchan_redis_storage_mode [distributed | backup | nostore]
context includes: location
```

Relevant documented semantics:

```text
distributed:
  messages publish through Redis and are retrieved in real time;
  multiple Nchan servers may share the Redis backend;
  horizontally scalable but pays Redis round-trip latency.

backup:
  messages publish locally first and later forward to Redis;
  Redis is used for persistence/channel initialization;
  only one Nchan server should use a Redis backend in backup mode.

nostore:
  messages publish as in distributed mode but are not stored.
```

Nchan 1.2.11+ explicitly made `nchan_redis_storage_mode` configurable in
`location` context; 1.3.8 retains this capability.

Do not rely only on prose interpretation.

Inspect the exact 1.3.8 implementation/config parser sufficiently to determine:

```text
- what storage mode on a subscriber-only location changes;
- whether a nostore subscriber location receives Redis pub/sub messages
  generated by a distributed publisher while avoiding Redis history/storage work;
- whether publisher=distributed + live-subscriber=nostore + history=distributed
  is semantically supported for one channel;
- whether a backup publisher on only p0 can coexist correctly with distributed
  subscriber/history locations on p1/p2/p3;
- whether mode is bound per request/location or creates channel-global state
  that would make mixed modes unsafe.
```

Use upstream 1.3.8 docs/source, not guesses.

Record a short decision note before running candidates:

```text
SUPPORTED
UNSUPPORTED
AMBIGUOUS — REQUIRES SMALL SMOKE
```

for each matrix candidate below.

Do not discard a supported candidate merely because it is unusual.

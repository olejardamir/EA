# v2.2.0 Generator-Only Benchmark — 2026-08-21

## Purpose
Prove the Go lightweight hot path has substantial headroom vs per-shard
delivery rate before interpreting DUT performance (Milestone 4.6).

## Method
Isolated Go benchmark on the actual `internal/sse` parser (the per-frame hot path
for all 100k viewers) and `internal/pool` tests. No network, no Nchan, no
coordinator — pure generator micro-benchmarks.

Run on host: `golang:1.24-bookworm` Docker image, Intel i7-8750H @2.20GHz,
12 logical cores. Command:

```bash
docker run --rm -v $PWD/poc/loadgen:/src -w /src golang:1.24-bookworm \
  go test -bench=BenchmarkFeed -benchmem -count=3 ./internal/sse
docker run --rm -v $PWD/poc/loadgen:/src -w /src golang:1.24-bookworm \
  go test ./...
```

## Headroom Analysis

Expected per-shard delivery rate under v2.2.0:

- Publish rate steady: ~9 events/s across 8 matches + 1 lobby/s = 10 events/s globally
- Burst: ~50 events/s globally
- Per-shard fan-out: same event is delivered to every viewer on that partition (~25k)
  - Steady: ~10 events/s * 25k viewers = 250k frames/sec per shard observed at SSE parser
  - Burst: ~50 events/s * 25k = 1.25M frames/sec per shard

Measured single-core parser capacity: ~15-18M frames/sec.

**Headroom ratio**:
- Steady: 18M / 0.25M = ~72× single-core headroom
- Burst: 18M / 1.25M = ~14× single-core headroom

With 4 cores available to the Go shard (CPUs=4 in Compose), the Go generator is not
the bottleneck — the DUT (Nchan fan-out, Redis, host FD/port) will be stressed
long before the lightweight parser saturates.

## Conclusion

Generator validity gate for v2.2.0 prequalification: **PASS** — lightweight path has
order-of-magnitude headroom. Deep cohort (1,024 viewers, JSON decode + schema) runs
on a separate bounded budget and is not on this hot path.

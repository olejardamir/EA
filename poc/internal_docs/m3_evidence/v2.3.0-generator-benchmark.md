# v2.3.0 Generator-Only Benchmark — 2026-08-22 (final hot path)

## Purpose

Diagnostic/headroom evidence for the final active v2.3.x source after all
integrity-closure changes (R01–R19). Non-qualifying: it does not replace
runtime validity, generator-health gates, or campaign evidence.

## Method

Isolated Go benchmarks on the actual hot-path components used by every one of
the 100k viewers:

- `internal/sse` `BenchmarkFeed` — SSE framing only.
- `internal/sse` `BenchmarkFullEventHotPath` — framing PLUS canonical_seq
  extraction (`ExtractCanonicalSeq`) — the full per-event hot path.
- `internal/tracker` `BenchmarkObserve` — transport-continuity state machine
  (`Tracker.Observe`), zero-allocation.
- `internal/deep` `BenchmarkValidateSchema` — deep-cohort schema validation.
- `internal/hist` `BenchmarkRecordSerialize` — histogram serialization.

canonical_seq extraction included: YES (`BenchmarkFullEventHotPath`,
plus dedicated `TestExtractCanonicalSeqHotPathAllocation` <=1 alloc).
continuity state machine included: YES (`BenchmarkObserve`).

Run in `golang:1.24-bookworm` Docker on Intel i7-8750H @2.20GHz, 12 logical
cores, host RAM 48 GB (~17 GB available). Command:

```bash
docker run --rm -v $PWD/poc/loadgen:/app -w /app -e GOCACHE=/tmp/gocache \
  golang:1.24-bookworm \
  go test -run '^$' -bench . -benchmem -count=3 ./internal/sse/ ./internal/tracker/
```

## Headroom interpretation

At the frozen terminal scale (100k viewers across 4 shards = 25k per shard,
steady accepted rate 10 events/s globally with fan-out delivery), the required
per-shard parse throughput is orders of magnitude below the measured ~11M
full-events/sec single-core capability of this host. The continuity tracker
adds a zero-allocation ~1.4 ns per observed sequence number. GC pressure from
the generator hot path is negligible (2 allocs/event, 88 B/event).
